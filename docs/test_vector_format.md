# Test Vector Format

Status: persistent vector contract for RTL unit tests, cocotb scoreboards, and AXI memory-model smoke tests. The legacy v0.1 files are still documented below; new randomized baseline and smoke vectors should be generated with `scripts/generate_test_vectors.py` and treated as reusable verification inputs, not temporary dumps.

## Deterministic Export v1

Use `scripts/generate_test_vectors.py` for new fixed-golden vectors:

```text
python -B scripts/generate_test_vectors.py --seed 100 --sequence-length 256 --dimension 64 --case-name baseline_s256_d64_seed100 --output-dir <dir>
python -B scripts/generate_test_vectors.py --seeds 100,101,102,103,104 --sequence-length 256 --dimension 64 --case-name baseline_s256_d64 --output-dir <dir>
python -B scripts/generate_test_vectors.py --seed 100 --sequence-length 4 --dimension 64 --case-name s4_d64_seed100 --output-dir test_vectors/generated/s4_d64_seed100
python -B scripts/generate_test_vectors.py --seed 7 --sequence-length 8 --dimension 8 --max-rows 4 --case-name smoke_s8_d8_seed7 --output-dir <dir>
```

Defaults and contract:

- Q/K/V are generated by `scripts.run_numeric_regression.generate_qkv`, using Python `random.Random(seed)` and no NumPy dependency.
- `O_golden` is generated by `model.golden_fixed.attention_fixed`, causal mode, default reciprocal `nr`, 32 LUT entries, one NR iteration, fixed four-cycle reciprocal valid latency.
- Default baseline shape is `S=256`, `D=64`, `STRIDE_BYTES=128`, `AXI_DATA_W=64`; small smoke cases may use lower `S`, lower `D`, and `--max-rows`.
- Q/K/V files always contain all `S` rows. `O_golden` contains `max_rows` rows when `--max-rows` is supplied, otherwise all `S` rows.
- Multi-seed CLI export suffixes the case name as `<case_name>_seed<seed>` to avoid file overwrite.

For case prefix `<case>`, the v1 file set is:

| File | Shape | Meaning |
|---|---:|---|
| `<case>_Q.hex` | `[S, D]` | Input Q, one signed int16 Q8.8 word per line. |
| `<case>_K.hex` | `[S, D]` | Input K, one signed int16 Q8.8 word per line. |
| `<case>_V.hex` | `[S, D]` | Input V, one signed int16 Q8.8 word per line. |
| `<case>_O_golden.hex` | `[output_rows, D]` | Fixed-golden output, one signed int16 Q8.8 word per line. |
| `<case>_Q_beats64.hex` | `[S, stride/8]` | 64-bit AXI beat image for Q, stride-padded. |
| `<case>_K_beats64.hex` | `[S, stride/8]` | 64-bit AXI beat image for K, stride-padded. |
| `<case>_V_beats64.hex` | `[S, stride/8]` | 64-bit AXI beat image for V, stride-padded. |
| `<case>_O_golden_beats64.hex` | `[output_rows, stride/8]` | 64-bit AXI beat image for O golden, stride-padded. |
| `<case>_metadata.json` | object | Machine-readable shape, source, endian, stride, and reciprocal metadata. |

Metadata fields used by RTL/cocotb consumers:

```json
{
  "format_version": "test_vector_format_v1",
  "layout": "row_major",
  "numeric_format": "Q8.8 signed int16",
  "word_hex": "one uppercase two's-complement int16 word per line",
  "beat64_endian": "little-endian bytes; WDATA[15:0] is lowest-column int16",
  "stride_bytes": 128,
  "axi_data_width": 64,
  "beats_per_row": 16,
  "reciprocal": {
    "mode": "nr",
    "lut_entries": 32,
    "nr_iterations": 1,
    "valid_latency": 4
  }
}
```

Do not check large generated vector directories into the repository. Keep generated baseline artifacts in an agreed regression/output area and preserve the command line plus metadata JSON for reproducibility. Small hand-picked smoke samples may be committed only when they are explicitly part of a test fixture.

### Committed S4/D64 End-to-End Fixture

`test_vectors/generated/s4_d64_seed100/` is the committed v1 end-to-end acceptance fixture for RTL `row_engine`, top-level AXI memory scoreboards, and cocotb bring-up. It is intentionally small enough to keep in git and is not a temporary dump.

The fixture was generated with:

```text
python -B scripts/generate_test_vectors.py --seed 100 --sequence-length 4 --dimension 64 --case-name s4_d64_seed100 --output-dir test_vectors/generated/s4_d64_seed100 --stride-bytes 128
```

It contains `Q`, `K`, `V`, and `O_golden` as both 16-bit word hex and stride-padded 64-bit AXI beat hex, plus `s4_d64_seed100_metadata.json`. Use `O_golden` for deterministic output comparison while RTL `row_engine`/top memory plumbing is being closed.

For top-level compute or AXI-memory smoke tests that want include-friendly constants, regenerate and include the checked-in SVH:

```text
python -B scripts/dump_fixture_sv.py --metadata test_vectors/generated/s4_d64_seed100/s4_d64_seed100_metadata.json --output sim/include/s4_d64_seed100_vectors.svh
```

`sim/include/s4_d64_seed100_vectors.svh` is intentionally small and deterministic. It contains:

- Shape constants: `S4_D64_SEED100_SEQUENCE_LENGTH=4`, `S4_D64_SEED100_DIMENSION=64`, `S4_D64_SEED100_BEATS_PER_ROW=16`, and `S4_D64_SEED100_O_GOLDEN_BEATS=64`.
- `$readmemh` path constants for Q/K/V/O `*_beats64.hex`, so a TB can load a 64-bit AXI memory model without hard-coding paths.
- Localparam arrays `S4_D64_SEED100_{Q,K,V,O_GOLDEN}_BEATS64[0:63]`, useful for direct initialization when a simulator or smoke TB does not want file I/O.
- `S4_D64_SEED100_o_golden_word(row, col)`, which extracts `beat[(lane * 16) +: 16]`; this matches the v1 little-endian lane rule where `WDATA[15:0]` is column 0 of each 4-lane beat.

A top compute S4 smoke should preload Q/K/V beats at the agreed base addresses with `row * STRIDE_BYTES + beat * 8`, run the top for `S=4,D=64,causal=1`, dump the O region as either 256 `words16` lines or 64 stride-padded `beats64` lines, and compare against `O_golden`.

`scripts/compare_vector_output.py` compares a DUT output file against the fixture metadata and golden output:

```text
python -B scripts/compare_vector_output.py --metadata test_vectors/generated/s4_d64_seed100/s4_d64_seed100_metadata.json --dut-hex <dut_output.hex> --format words16 --require-mae 0 --require-maxae 0
python -B scripts/compare_vector_output.py --metadata test_vectors/generated/s4_d64_seed100/s4_d64_seed100_metadata.json --dut-hex <dut_output_beats64.hex> --format beats64 --require-mae 0 --require-maxae 0
```

The comparator reports `MAE`, `MaxAE`, maximum LSB error, and the first failing row/column. A nonzero process exit means the requested threshold failed or the input format was invalid.

When the S4 smoke is stable, expand to `S=256,D=64` with the same generator and metadata contract, but do not commit the full generated directory by default. Keep the large baseline vectors in the regression artifact area, commit only small manifests or selected smoke includes, and reuse the same comparator in `beats64` mode for top-memory dumps.

### Cycle Model Mapping for Round 6 Top Compute

Use `scripts/cycle_bandwidth_model.py` as the shared A/B contract for top-compute schedule estimates. The RTL parameters map to model arguments as follows:

| RTL / TB parameter | Cycle model argument | Meaning |
|---|---|---|
| `SEQUENCE_LENGTH` | `--sequence-length` | Logical S for the full attention problem. Baseline target remains `256`. |
| `DIMENSION` | `--dimension` | Feature dimension D. Baseline target remains `64`. |
| `COMPUTE_ROWS` | `--compute-rows` | Number of output Q/O rows produced by the top-compute invocation. `--max-rows` is retained as a legacy alias and must match when both are supplied. |
| `KV_TILE_ROWS` | `--kv-tile-rows` | Number of K/V rows in each reusable tile. Round 6 baseline studies should compare at least `16` and `32`. |
| K/V tile reuse enabled | `--reuse-kv-tile` | Active model path uses tile-reuse traffic. `--no-reuse-kv-tile` forces the sequential no-reuse budget path for comparison. |

The report now emits both traffic paths for every scenario:

- `sequential_*`: Q is read once, and K/V are read for every causal score. This approximates the current straightforward schedule without K/V tile reuse.
- `tile_reuse_*`: Q is read once, K/V rows are read once across `KV_TILE_ROWS` chunks for the `COMPUTE_ROWS` output tile, and O is written once. This is the Round 6 target direction.
- `read_bytes`, `read_beats`, `dma_cycles`, `total_cycles`, and `under_cycle_budget` follow the active path selected by `reuse_kv_tile`.

Useful checks:

```text
python -B scripts/cycle_bandwidth_model.py --sequence-length 4 --dimension 64 --compute-rows 4 --kv-tile-rows 4 --json
python -B scripts/cycle_bandwidth_model.py --sequence-length 256 --dimension 64 --compute-rows 256 --kv-tile-rows 16 --json
python -B scripts/cycle_bandwidth_model.py --sequence-length 256 --dimension 64 --compute-rows 256 --kv-tile-rows 32 --json
python -B scripts/cycle_bandwidth_model.py --sequence-length 256 --dimension 64 --compute-rows 256 --kv-tile-rows 16 --no-reuse-kv-tile --json
```

Round 6 status boundary: the committed S4/D64 fixture and top-compute smoke are functional evidence for data plumbing and fixed-golden comparison. They are not yet PPA or baseline proof. Baseline signoff still needs an `S=256,D=64` tile schedule, PPA runs on the parameterized top, and larger regression artifacts using the same v1 metadata/comparator contract.

## Legacy File Set v0.1

## File Set

Each test case uses this prefix:

```text
test_vectors/test_NNN
```

where `NNN` is a zero-padded decimal test id.

Existing files per case:

| File | Shape | Meaning |
|---|---:|---|
| `test_NNN_Q.hex` | `[256, 64]` | Input Q, signed int16 Q8.8. |
| `test_NNN_K.hex` | `[256, 64]` | Input K, signed int16 Q8.8. |
| `test_NNN_V.hex` | `[256, 64]` | Input V, signed int16 Q8.8. |
| `test_NNN_O_ref.hex` | `[256, 64]` | FP32 SDPA reference output quantized to signed int16 Q8.8. |
| `test_NNN_O_q88.hex` | `[256, 64]` | Current Q8.8-simulated FlashAttention output quantized to signed int16 Q8.8. |

Each file has exactly `256 * 64 = 16384` lines.

## Element Encoding

- One element per line.
- Four uppercase hexadecimal digits.
- No `0x` prefix.
- Two's-complement signed int16.
- Numeric interpretation is signed Q8.8:

```text
signed_value = int16(hex_word)
float_value  = signed_value / 256.0
```

Examples:

| Hex | int16 | Q8.8 value |
|---|---:|---:|
| `0100` | 256 | 1.0 |
| `FF00` | -256 | -1.0 |
| `8000` | -32768 | -128.0 |
| `7FFF` | 32767 | 127.99609375 |

## Row-Major Order

All tensors are flattened row-major:

```text
line_index = row * 64 + col
row        = line_index / 64
col        = line_index % 64
```

For `Q`, `K`, `V`, and `O`, `row` is the sequence index `0..255`, and `col` is the feature dimension `0..63`.

The current SystemVerilog tests load vectors with:

```systemverilog
logic [15:0] q_mem [256 * 64];
$readmemh("test_vectors/test_000_Q.hex", q_mem);
q_elem = $signed(q_mem[q_index * 64 + dim]);
```

## `O_ref` vs `O_q88`

`O_ref`:

- Generated by FP32 standard SDPA.
- Applies causal mask.
- Computes full softmax in FP32.
- Quantizes final FP32 output to Q8.8.
- Best reference for algorithmic correctness.

`O_q88`:

- Generated by the current Q8.8-simulated FlashAttention path.
- Uses tiled online softmax.
- Uses exp/reciprocal approximations from `golden_model.py`.
- Quantizes final output to Q8.8.
- Best reference for fixed-point/RTL approximation once RTL adopts the same rules.

Bring-up recommendation:

- Use `O_ref` for end-to-end correctness tolerance checks.
- Use `O_q88` for fixed-point conformance checks after v1.0 formats and approximations are frozen.
- Do not require bit-exact `O_q88` matching yet; v0.1 fixed-point rules still have open items.

## AXI Memory Byte Order

The hex files are word-oriented for `$readmemh`. For AXI memory models, store each int16 element little-endian in byte-addressed memory:

```text
addr(tensor[row][col]) = BASE + row * STRIDE_BYTES + col * 2
byte[addr + 0] = hex_word[7:0]
byte[addr + 1] = hex_word[15:8]
```

Default `STRIDE_BYTES = 128`, because each row has `64 * 2` bytes.

Example for hex word `3608`:

```text
int16 word = 16'h3608
memory[addr + 0] = 8'h08
memory[addr + 1] = 8'h36
```

On a 64-bit AXI data bus, four adjacent int16 elements occupy one beat:

```text
WDATA[15:0]  = elem[col + 0]
WDATA[31:16] = elem[col + 1]
WDATA[47:32] = elem[col + 2]
WDATA[63:48] = elem[col + 3]
```

This follows little-endian byte lanes. If a simulator stores `logic [15:0] mem[]` words directly with `$readmemh`, no byte swap is needed.

The v1 `*_beats64.hex` files write one 64-bit beat per line using the same lane mapping. Since a text hex line is printed most-significant nibble first, the line for elements `[elem0, elem1, elem2, elem3]` is:

```text
<elem3><elem2><elem1><elem0>
```

Rows are padded with zero beats out to `STRIDE_BYTES`. For the baseline `D=64`, `STRIDE_BYTES=128`, each row has 16 beats and no element padding. For a smoke case such as `D=8`, each row has two data beats followed by fourteen zero beats.

## RTL Read Rules

For current non-AXI smoke tests:

- Use `$readmemh` directly into a `logic [15:0] mem [S*D]` array.
- Index as `mem[row * D + col]`.
- Cast to signed before arithmetic: `$signed(mem[index])`.

For future AXI memory model tests:

- Load hex as int16 words.
- Expand to little-endian bytes in the memory model.
- Respect `BASE` and `STRIDE_BYTES`.
- Q/K/V/O each occupy 32 KiB with default stride.
- Or load the v1 `*_beats64.hex` files directly into a 64-bit beat memory model, preserving row-major stride order.

## Random Full-Row Baseline Case

`scripts/generate_corner_vectors.py` also emits one reproducible randomized full-row case:

```text
test_vectors/cases/random_full_row_seed20240623_Q.hex
test_vectors/cases/random_full_row_seed20240623_K.hex
test_vectors/cases/random_full_row_seed20240623_V.hex
test_vectors/cases/random_full_row_seed20240623_O_ref.hex
test_vectors/cases/random_full_row_seed20240623_O_q88.hex
test_vectors/cases/random_full_row_seed20240623_meta.txt
test_vectors/debug/random_full_row_seed20240623/row000_expected.txt
```

The tensor files follow the normal `[256, 64]` row-major Q8.8 format, one uppercase 16-bit word per line. The random Q/K/V contents come from Python's deterministic `random.Random(20240623)` stream, so they do not depend on NumPy availability. The meta file is ASCII `key=value` and records `seed=20240623`, `S=256`, `D=64`, `BK=32`, `causal=1`, `scale=1/8`, the output meanings, backend/mode labels, and summary error fields:

```text
mae_vs_fp32=<float>
max_ae_vs_fp32=<float>
worst_row=<decimal row index>
row_mae_min=<float>
row_mae_max=<float>
row_max_ae_min=<float>
row_max_ae_max=<float>
```

`O_ref` is FP32 SDPA quantized to Q8.8. `O_q88` is the current pure-Python Q8.8 FlashAttention-style simulated output quantized to Q8.8, using the generator's recorded `exp_mode` and `recip_mode`. This case is intended for full-row scoreboard/golden plumbing and regression reproducibility; it does not freeze the final exp/recip LUT/PWL bit-exact contract.

The debug `row000_expected.txt` file is an RTL-scoreboard-consumable ASCII expected pack for query row 0. It records:

```text
case=random_full_row_seed20240623
q_index=00
source_o_q88=test_vectors/cases/random_full_row_seed20240623_O_q88.hex
not_rtl_pass_evidence=1
lane00_o_q88_hex=<first O_q88 word>
...
lane63_o_q88_hex=<64th O_q88 word>
```

The 64 lane values must match the first 64 words of `random_full_row_seed20240623_O_q88.hex` exactly. `not_rtl_pass_evidence=1` means this file is generated golden input for the RTL scoreboard, not evidence that RTL has passed it.

## Deterministic Row Scoreboard Expected

`test_vectors/debug/row_scoreboard_s4_det/expected.txt` is a small deterministic expected pack for row-level scoreboard bring-up. It keeps the same ASCII key/value style as the other debug expected files, records `q_index=03`, `S_active=4`, `D=64`, four valid score/exp contributions, and exactly 64 `laneDD_o_q88_hex` output lines.

The matching input files live beside the other corner-case vectors:

```text
test_vectors/cases/row_scoreboard_s4_det_Q.hex
test_vectors/cases/row_scoreboard_s4_det_K.hex
test_vectors/cases/row_scoreboard_s4_det_V.hex
```

They use the normal flat `[256, 64]` row-major Q/K/V format, one uppercase 16-bit Q8.8 hex word per line. The controlled row is `q=3`: `Q[3][0]=0100` and all other Q lanes are zero. K rows `0..3` provide the four score points with `K[0][0]=0000`, `K[1][0]=FC00`, `K[2][0]=F000`, and `K[3][0]=E000`; other K lanes are zero. V rows `0..3` copy the `laneDD_v0_q88_hex` through `laneDD_v3_q88_hex` values from `expected.txt` on lanes `00`, `01`, `02`, `07`, `31`, and `63`; all other V entries are zero.

Use this file to validate scoreboard parsing and complete D-lane row comparison before the full random/full-row golden flow is ready. It is not a replacement for `test_NNN_O_ref.hex`, `test_NNN_O_q88.hex`, or any eventual full `S=256` randomized golden, and it does not freeze the final exp/recip approximation contract.
